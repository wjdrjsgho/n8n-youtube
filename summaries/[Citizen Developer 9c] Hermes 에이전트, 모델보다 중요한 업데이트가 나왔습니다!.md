## **할미스 에이전트 업데이트 주요 개선 사항**

- 할미스 에이전트 활용 중 실제 업무를 맡기는데 아쉬운 부분이 있었음.

- 무엇을 물어보면 답변이 뜰 때까지 한참 기다려야 하는 경우가 있음.

- 위험해 보이는 명령이 올라오면 매번 수동으로 검토하여 직접 승인해 줘야 하므로, 승인 지연으로 작업이 밀리는 케이스가 발생함.

- 복잡한 작업을 시켜 놓고 나면 작업 진행 현황을 확인할 수 없어 답답한 경우가 있음.

- 이러한 아쉬움들 때문에 뮤스 에이전트를 설치하여 일을 시키기는 하지만, 마음 놓고 완전히 맡기기는 어려웠던 경우가 있음.

- 최근 비스미스 에이전트 업데이트에서 이러한 아쉬움을 하나씩 해결해 줬음.

- 확실히 완성도가 올라갔다는 느낌을 받았음.

- 업데이트된 헬멧스 에이전트가 AI 비서로서 얼마나 완성도 높아졌는지 예시와 함께 확인해볼 예정임.

## **주요 업데이트 내용 요약**

- 정확히 어떤 부분들이 업데이트를 통해 개선되었는지 짚어볼 필요 있음.

- <strong>속도 개선</strong>:

- 특히 할미스 에이전트 처음 실행 시 '콜드 스타트' 시간이 꽤 오래 걸리던 부분들이 개선되었음.

- 단순 실행 속도뿐만 아니라, 결제 때문에 작업이 멈추는 케이스가 많이 발생했던 문제도 개선됨.

- <strong>스마트 모드 기본 탑재 (결제 과정 개선)</strong>:

- 위험한 작업이 아니면 에이전트가 알아서 승인하고 작업을 진행할 수 있게 됨.

- 위험한 명령어만 직접 수동으로 승인받도록 설정되었음.

- <strong>실시간 작업 현황 관찰 기능 개선</strong>:

- 작업이 진행되는 동안 에이전트가 어떤 작업을 실시간으로 하고 있는지를 좀 더 쉽게 확인할 수 있게 기능이 개선됨.

- <strong>작업 완료 후 검증 기능 강화</strong>:

- 작업이 완료되었을 때 검증을 좀 더 제대로 해줌.

- 특히 '골(Goal)' 기능을 활용하면 증거 검증을 자동으로 해줌.

- <strong>결과물 전달 안정성 향상</strong>:

- 검증까지 해서 결과물이 생성되었을 때, 생성된 결과물을 제대로 전달하지 못하고 중간에 중단되었을 때도 결과 전달을 좀 더 제대로 할 수 있게 도와줌.

- 이러한 업데이트로 빨라진 속도로 결제도 센스 있게 알아서 하고, 관찰도 더 잘할 수 있으며, 검증까지 해서 전달도 좀 더 안정적으로 해 주게 되었음.

- 구체적인 기능 관점에서 보면, 대부분 가장 최근 업데이트에서 추가된 기능들이며, 검증 부분만 이전 버전에서 업데이트된 기능임.

- 구체적인 기능들은 실제 예시와 함께 살펴볼 예정임.

- 참고로 할미스 에이전트 설치 방법이나 데스크톱 앱 설치 방법은 이전 영상에서 정리해 뒀으므로, 필요시 참고하면 됨.

- 호스팅어 VPS를 활용해 데스크톱 앱을 호스팅어 서버와 연동하여 셋업해 둔 환경으로 테스트를 진행할 예정임.

## **속도 개선 및 첫 응답 지연 단축**

- 데모 인풋으로 고객 문의 30건을 샘플로 CSV 파일에 저장해 둠.

- 이 문의들을 분류하고 FAQ 답변을 생성하는 업무를 시켜볼 예정임.

- 데스크톱 앱 설치 및 연동 후 화면이 다르게 뜨는 경우, 우측 상단 '레이아웃 에디터'를 통해 원하는 형태로 레이아웃 변경 및 커스텀이 가능함.

- 포커스 모드를 선호하여 포커스 모드로 설정함.

- 생성해 둔 프로필 중 '뉴턴'을 활용하여 속도 테스트를 진행함.

- "들리니? 너 이름이 뭐지?" 요청 시, 바로 "뉴턴이고 구실 컴퍼니의 리서치 팩트 담당 AI다."라고 답변해 줌.

- 이전 버전과 정확한 비교는 어렵지만, 처음 답변해 주는 것이 빠르다는 느낌을 받았음.

- 현재 설정은 코덱스에서 패스트의 하이 레이턴시로 설정된 상태임.

- 단순히 첫 응답 지연을 단축시키는 것도 의미가 있지만, 더 중요한 것은 답변 과정에서 에이전트가 어떤 작업을 하는지 중간중간 실시간으로 확인할 수 있으면 덜 답답하다는 점임.

## **실시간 작업 현황 관찰 (Live Reasoning)**

- 할미스 업데이트 시 자동으로 반영되어 있는 기능임.

- 데스크톱 앱에서 '뉴턴' 프로필 선택 후, 우측 상단 '세팅스'의 '채팅' 쪽에 있는 '리즈닝 블락' 토글을 켜줌.

- 이것은 '리즈닝 섹션'을 확인할 수 있게 보여 달라는 기능을 켜 주는 것임.

- 간단한 요청으로 테스트 진행함.

- CSB 파일이 들어있는 '커스터머 서비스' 프로젝트를 이미 설정해 둠.

- 요청 내용: "CSB 파일을 읽고 각 문의를 배송, 환불, 계정 중에 하나로 분류하고 FAQ 초안으로 만들 거다. 지금은 일단 계획부터 수립해 줘."

- '리즈닝 블락' 토글을 켰기 때문에, 모델이 작업 요청을 했을 때 '띵킹(Thinking)'하는 과정을 실시간으로 확인할 수 있음.

- '띵킹'을 눌러보면 어떤 작업을 하고 있는지 실시간으로 확인 가능함.

- 간단한 요청이었기에 '다큐먼트 워플로 애널리시스 플래닝' (툴콜), '아웃라인 포스텝' (띵킹) 등 한두 단계만 진행 후 답변을 줌.

- 어떤 생각을 하고 답변을 한 것인지 이 과정을 투명하게 확인할 수 있게 되었음.

## **스마트 어프로벌 (Smart Approval) 기본 탑재**

- 결제 과정에서 '스마트 어프로벌'이 기본으로 탑재되었음.

- 위험한 요청이 아니면 알아서 승인하고 작업을 진행해 줌.

- 간단한 요청으로 테스트 진행함.

- "수정하지 말고 헤더랑 데이터 행 수만 체크해라." 요청 시, 바로 체크해 주는 것을 볼 수 있음.

- '띵킹' 후 파이썬 명령어 실행으로 즉시 체크 결과 확인 가능함.

- 이처럼 위험하지 않은 명령의 경우, 스마트 어프로벌이 디폴트로 탑재되었기 때문에 바로 실행됨.

- '스마트 어프로벌' 설정은 우측 하단 '어프로벌 모드'에서 '스마트'가 선택되어 있음.

- '매뉴얼'이나 '오프'로도 수정 가능함.

- 이번에는 삭제를 요청하는 프롬프트를 줘 봄.

- 이는 상대적으로 위험하다고 판단될 수 있는 요청이기에, 바로 진행하지 않고 승인 요청을 함.

- "이대로 진행할 건지?" 요청이 뜨며, 커맨드도 확인할 수 있음.

- 'Run'을 하면 승인, 'Reject'를 하면 실행을 막을 수 있음.

- 디폴트를 '스마트'로 두면 낮은 위험의 업무를 매번 승인해 줘야 하는 필요를 줄이면서, 위험하거나 애매한 작업은 항상 결제를 받도록 설정할 수 있음.

- 데스크톱 앱 외에도 CLI, 텔레그램, 슬랙 등에서 동일하게 이 모델을 설정하고 활용할 수 있음.

## **서브 에이전트 실시간 관찰 기능**

- 메인 에이전트가 작업할 때의 '띵킹' 과정 확인뿐만 아니라, 서브 에이전트들이 작업할 때도 실시간으로 각 서브 에이전트별로 어떤 작업을 하고 있는지 확인하는 기능이 추가됨.

- 앞서 수립한 5단계 계획에 따라 작업을 요청해 봄.

- "앞서 세운 5스텝 계획대로 실행해 줘." 요청 시, 서브 에이전트를 3개로 나눠 실행하도록 프롬프트를 작성함.

- 복잡한 작업을 할 때 할미스 에이전트 데스크톱 앱에서 먼저 스텝들을 정리해 줌.

- 5개 단계로 작업이 정리된 것을 투명하게 확인 가능함.

- 서브 에이전트 3개가 화면 하단에 떠 있는 것을 볼 수 있음.

- 각 서브 에이전트를 클릭하면 팝업이 뜨고, 어떤 작업을 실행하는지(예: 터미널 작업)까지 모두 확인할 수 있음.

- '에이전트' 버튼을 누르면 3개를 한 번에 확인 가능하여, 대략적으로 각 서브 에이전트별 작업 현황을 한눈에 파악할 수 있음.

- 프롬프트에서 각 서브 에이전트의 '띵킹' 과정도 바로 실시간으로 확인 가능함.

- 이전에는 서브 에이전트 작업 완료까지 기다려야 했다면, 이제는 중간중간 서브 에이전트의 작업 현황을 손쉽게 확인할 수 있게 됨.

- 작업 완료 후 결과 요약과 최종 산출물(분류표 및 카테고리별 FAQ 초안)이 생성되었고, 다운로드 및 파일 저장 경로 확인 가능함.

## **골(Goal) 기능 활용한 검증 강화 (`/goal` 및 Completion Contract)**

- '골' 기능(Completion Contract)을 활용하여 목표를 줄 때, 어떤 기준에 도달하면 멈추면 된다는 기준을 설정할 수 있음.

- 설정된 기준에 따라 코딩으로 검증해 주는 프로세스가 추가되었음.

- 동일한 작업에 '골' 기능을 활용하여 작업 요청해 봄.

- 슬래시(`/`) 입력 후 '골' 명령어를 추가함.

- 요청 프롬프트: "고객 문의 30건 분류 FAQ 초안 작성 해줘. 기존 아웃풋 먼저 제거하고 새롭게 작업 진행해 줘."

- <strong>베리피케이션 (검증) 조건</strong>: "분류 결과 개수 30개, 중복 없고 누락 없고, FAQ 파일에 세 카테고리 섹션 모두 존재."

- <strong>제약 조건</strong>: "원본 CSV 수정하지 말고, 인풋/아웃풋 안에서만 작업."

- <strong>중단 조건</strong>: "애매한 문의가 세 건 넘으면 멈추고 물어봐."

- 요청 시 `/goal` 명령어가 위쪽에 입력된 것을 확인 가능하며, 골 기능에 따라 작업이 진행됨.

- 이번에도 태스크를 단계로 나눠 실행하는 것을 볼 수 있음.

- 기존 아웃풋을 먼저 삭제하고 작업을 진행하며, 앞서 설정한 검증 조건들('중복 없음', '누락 없음', '세 카테고리 섹션 존재')을 마지막 단계에서 검증하도록 단계가 설정됨.

- 작업 완료 후, 결과 및 분류 결과 사유까지 제공하며, 중단 기준(애매한 문의 세 건 초과)은 넘지 않아 작업이 진행되었다고 알려줌.

- 산출물로 '검증 결과 제이슨 파일'까지 생성해 줌.

- 파일 확인 시 실제로 검증한 이력까지 생성된 것을 볼 수 있음.

- 여러 번 반복해서 진행해야 하고 명확한 중단 기준이나 검증 기준이 존재할 때는 `/goal` 기능을 활용하여 작업을 요청하면, 좀 더 체계적으로 검증하고 결과 보고를 해 주게 됨.

## **안정적인 결과 전달 (Delivery Obligation Ledger)**

- 보통 해당되지는 않지만, 결과물이 생성되었는데 슬랙이나 텔레그램 등으로 전달되어야 할 때 뭔가 이슈가 발생하여 누락되는 경우가 있었음.

- 이전에는 이런 경우 새롭게 다시 요청해야 하는 경우가 많았으나, 이제 개선되었음.

- '딜리버리 어플리케이션 레저(Delivery Obligation Ledger)'가 생성되면서 위임 결과 내구성이 향상되었다고 안내함.

- 이는 결과가 생성되지 않았는데 알아서 이어서 작업을 한다는 의미는 아니며, *결과가 생성되었으나 전달이 누락되었을 때* 복구할 수 있는 기능임.

- 혹시라도 커넥션 이슈 등으로 결과물이 생성됐으나 누락된 것 같을 때, 업데이트를 해 두면 그런 부분들을 복구하기 더 좋아졌다고 볼 수 있음.

- 이 다섯 가지 업데이트는 모델이 더 똑똑해졌다기보다는, 우리가 일을 맡기고 실행하는 과정에서 안정성을 높여주게 업데이트되었다고 판단됨.

## **그 외 지속적인 업데이트**

- 할미스 에이전트는 운영에 도움 되는 여러 가지 업데이트를 지속적으로 진행 중임.

- <strong>`/arn` 기능</strong>: 더 손쉽게 스킬을 생성할 수 있도록 도움.

- <strong>MOA (Mixture of Agents) 기능</strong>: 여러 모델을 믹스하여 사용 가능.

- <strong>시크릿 정보 관리 기능</strong>: 시크릿 정보를 더 효율적으로 관리.

- 관심이 있다면 에이전트 업데이트 후 시스템에 적용해 보면 좋을 것임.

## **할미스 에이전트 업데이트 방법 (호스팅어 VPS 사용자)**

- 호스팅어 VPS를 활용하는 경우, 사용하고 있는 도커 프로젝트에서 '...' 버튼을 클릭하면 '업데이트' 버튼이 보임.

- 이 '업데이트' 버튼만 누르면 도커에서 할미스 에이전트가 바로 업데이트됨.

- 업데이트 버튼을 눌러 업데이트하고 활용해 볼 수 있음.

## **마무리**

- 어떤 업데이트가 가장 도움이 되는지 댓글로 의견을 남겨주시면 좋을 것 같음.

- 생산성을 높일 수 있는 시스템을 구축하는 방법을 가지고 다시 찾아뵙도록 하겠음.

- 관심 있는 경우 구독과 좋아요, 알림 설정을 해주시면 감사하겠음.
