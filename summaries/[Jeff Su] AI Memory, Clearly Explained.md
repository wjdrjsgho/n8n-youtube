## **AI 챗봇 메모리 기능에 대한 오해와 영상 소개**

- 대부분의 사용자가 AI 챗봇의 메모리 기능을 활성화할 때, 중요한 정보를 모두 기억할 것이라고 기대하지만, 실제로는 그렇지 않음.

- 이는 AI 회사들이 과장된 약속을 하지 않는 것으로 알려져 있기에 의아한 부분임.

- 본 영상에서는 AI가 자동으로 생성하는 메모리 기능이 의도적으로 나쁜 이유와 세 가지 AI 메모리 레벨(가장 기본적인 버전부터 사용자 제어 시스템까지)을 상세히 다룰 예정임.

## **레벨 1: 글로벌 메모리**

- <strong>개념 및 특징</strong>

- 글로벌 메모리는 사용자가 메모리 기능을 활성화한 후 AI 챗봇이 자동으로 생성하는 계정 수준의 사실 및 선호 사항을 의미함.

- 이러한 내용은 사용자의 모든 채팅에 적용됨.

- <strong>예시: 고난이도 프레젠테이션 준비</strong>

- ChatGPT와 몇 시간 동안 프레젠테이션을 작업하는 상황을 가정함.

- 이상적인 시나리오는 AI가 "사용자는 Satya Nadella와 Tim Cook에게 마이크로 아이폰을 피칭하는 중요한 프레젠테이션을 준비 중임. 슬라이드 V1이 확정되었고, 다음은 시각적 보완 작업임"과 같은 내용을 기억하는 것임.

- 이후 사용자가 언제 다시 돌아오든 이전 세션에서 중단했던 부분부터 정확히 이어서 작업할 수 있기를 기대함.

- 그러나 실제로는 그렇지 않음.

- 다음 날 새로운 채팅에서 프레젠테이션에 대해 물었을 때, AI는 이전에 작업한 프레젠테이션이나 이전 세션의 맥락, 피드백, 학습 내용을 전혀 알지 못함.

- <strong>AI의 자동 생성 메모리 확인</strong>

- 사용자 스스로 AI의 자동 생성 메모리를 확인하여 이 사실을 직접 확인할 수 있음.

- ChatGPT의 경우, '개인화(personalization)' 섹션의 '메모리(memory)' 관리(manage)에서 확인할 수 있음.

- 여기서 특정 프로젝트나 작업 흐름에 대한 정보는 거의 저장되어 있지 않음을 알 수 있음.

- 하지만 사용자의 역할이나 글쓰기 선호도와 같은 고수준의 정보는 기억하고 있음.

- <strong>설계 의도: 왜 고수준 정보만 기억하는가?</strong>

- 계정 수준에 저장되는 모든 정보(글로벌 메모리)는 모든 미래 채팅에 끌려들어 가기 때문에, AI는 의도적으로 이를 얇게 유지함.

- 잘못된 정보가 저장될 경우, 모든 채팅에 악영향을 미칠 수 있기 때문임.

- 사용자가 직장 관리자, 부모, 자녀, 배우자, 형제자매, 사업가, 골프 플레이어 등 다양한 역할을 수행한다고 가정할 때, 한 맥락에서 유용한 정보가 다른 맥락에서는 완전히 관련 없을 수 있음.

- AI가 모든 정보를 글로벌 수준에서 저장하려 한다면, 모든 새 채팅에 관련 없는 맥락이 많이 포함되어 출력 품질이 저하될 수 있음.

- 따라서 글로벌 메모리는 사용자의 삶의 모든 부분에 적용되어야 하므로 고수준으로 유지되며, AI는 기억할 세부 사항을 결정할 때 더 적게 기억하는 경향을 보임.

- <strong>두 가지 우회 해결책</strong>

- <strong>명시적인 메모리 업데이트 지시</strong>

- 대화 중간에 AI에게 "메모리를 업데이트해줘. 10월 6일에 중요한 프레젠테이션이 있어"라고 명시적으로 지시할 수 있음.

- 메모리 페이지가 실제로 업데이트되는 것을 확인할 수 있음.

- 그러나 사용자가 매번 이를 기억하고 요청해야 하며, 이 새로운 항목이 AI가 관리하는 동일한 얇은 글로벌 프로필에 저장되어 관련 없는 채팅에도 따라다닌다는 점이 문제임.

- <strong>외부 도구 연결</strong>

- Google Drive와 같은 도구를 연결한 다음 AI에게 "Nutella 쿠키 거래에 대한 최신 회의록을 가져와 맥락으로 사용해줘"라고 지시할 수 있음.

- 이 또한 AI에게 필요한 정보를 제공할 수 있음.

- 하지만 이 방법도 문제가 있음. 해당 프레젠테이션에 대한 회의가 없었을 수도 있고, 커넥터는 ChatGPT 내에서 이전 작업 세션에서 무슨 일이 있었는지 알지 못함.

- <strong>다른 챗봇의 경우</strong>

- Claude와 Gemini도 자체적인 글로벌 메모리 버전을 가지고 있으며, 정확히 똑같이 작동함.

- <strong>레벨 1 요약</strong>

- AI가 사용자에 대한 계정 수준 메모리를 작성하며, 이는 모든 채팅에 적용됨.

- 삶의 다양한 역할에 걸쳐 필요한 고수준 정보에는 유용함.

- 그러나 실제 작업을 위한 충분한 특정 맥락은 절대로 저장하지 못함.

## **스폰서 광고: Granola - AI 노트패드로 대면 대화의 빈틈 채우기**

- 기존 워크플로우는 Google Drive에서 회의록을 AI로 바로 가져왔지만, 대면 대화와 같은 현장 대화 기록에는 치명적인 빈틈이 있었음.

- 오늘의 스폰서 Granola는 Google Meet, Zoom, Teams와 같은 모든 플랫폼에서 작동하며 이 문제를 해결함.

- <strong>Granola 소개</strong>

- Granola는 사용자와 함께 노트의 빈틈을 채워주는 AI 노트패드임.

- Gemini만큼 정확하게 필사하는 유일한 앱으로 확인됨.

- <strong>기존 워크플로우의 비효율성</strong>

- 과거에는 음성 메모로 대화를 녹음하고, Gemini에 오디오를 업로드하여 필사본을 생성하고, 다운로드한 다음, 다른 AI와 공유하여 처리하는 식이었음.

- <strong>Granola를 통한 개선된 워크플로우</strong>

- 이제 대면 커피 채팅 전에 휴대전화에서 Granola를 열기만 하면 됨.

- AI 강화 노트 기능 덕분에, 기록된 필사본을 사용하여 간단히 작성한 약식 노트를 풍부하게 보완할 수 있음.

- 최근 커피 채팅에서 지저분한 노트 두 줄만 썼는데, Granola가 작성한 내용을 바탕으로 깔끔한 요약과 액션 아이템을 생성해주었음.

- 이는 일반적인 필사본이 아닌 사용자 노트처럼 읽히게 됨.

- Granola를 ChatGPT 및 Claude와 연결했기 때문에, 해당 노트들을 불러와 브리핑을 받고 요약 이메일을 초안 작성하도록 요청할 수 있음.

- 신규 사용자는 아래 링크를 통해 첫 달 100% 할인을 받을 수 있음.

## **레벨 2: 프로젝트 메모리**

- <strong>개념 및 특징</strong>

- 프로젝트 기능은 하나의 특정 작업 흐름이나 반복되는 작업에 대한 경계를 설정함.

- 해당 프로젝트 내의 모든 채팅이 동일한 주제에 관한 것이므로, AI는 다른 모든 채팅에 세부 정보를 끌어들이지 않고 실제 작업에 대한 훨씬 더 구체적인 메모리 항목을 생성할 수 있음.

- 레벨 1의 글로벌 메모리는 여전히 계승되어, 프로젝트 내의 모든 채팅은 계정 수준 메모리와 더 구체적인 프로젝트 수준 맥락을 모두 얻게 됨.

- <strong>예시: Claude 프로젝트</strong>

- Claude 프로젝트 내에서 프로젝트 수준 메모리를 볼 수 있지만, 이를 직접 편집할 수는 없음.

- 즉, Claude(또는 AI)가 무엇을 기록하고 무엇을 생략할지 여전히 결정함.

- <strong>장점</strong>

- AI가 특정 작업 흐름과 관련된 규칙과 맥락을 자동으로 기억한다는 점은 훌륭함.

- 예를 들어, 프레젠테이션 프로젝트에서 "이 프레젠테이션의 다음 단계는 무엇인가?"라고 물었을 때, Claude는 버전 1 슬라이드가 완성되었고 다음은 시각적 보완 작업이라고 정확하게 답변함.

- <strong>문제점: AI가 중요성을 판단</strong>

- AI는 사용자가 아는 것만큼 무엇이 중요한지 잘 알지 못함.

- 예를 들어, "모든 참석자 이름을 알 수 있도록 참석자 명단을 알려줘"라고 물었을 때, Claude는 부분적인 목록만 제공함.

- 일주일 전에 캘린더 초대장 스크린샷을 채팅에 붙여 넣었음에도 불구하고, AI는 당시 스크린샷을 잘 읽었지만, 그 이름들이 저장할 만큼 중요하지 않다고 판단했기 때문임.

- 따라서 레벨 2의 문제는 AI가 여전히 작성자이며, 무엇을 포함하고 무엇을 제외할지 결정한다는 점임.

- 만약 Claude가 오래된 메모리 항목에서 정보를 가져와서 잘못된 프레젠테이션 날짜로 관리자에게 업데이트 초안을 작성한다면 좋지 않을 것임.

- <strong>우회 해결책: 수동 업데이트</strong>

- 레벨 1과 유사하게, 레벨 2의 우회 해결책은 AI를 수동으로 수정하는 것임.

- Claude의 메모리 카드에서 직접 "프로젝트 메모리를 업데이트해줘"라고 말하거나, 프로젝트 수준 채팅에서 명시적으로 "프로젝트 메모리를 업데이트해줘, Tim Cookie와 함께 John Turnip도 참석이 확정되었어"라고 말할 수 있음.

- 이것으로 참석자 목록을 수정할 수 있음.

- 그러나 레벨 1의 한계는 여전히 적용됨. 사용자가 문제를 인지하고, 수정 사항을 기억하고, AI에게 무엇을 수정할지 알려야 함.

- 이는 지속 가능하지 않으며, AI 메모리의 목적을 어느 정도 무력화함.

- <strong>레벨 2 요약 및 근본 문제점</strong>

- 프로젝트는 AI에게 훨씬 더 좁은 경계를 제공하여, 하나의 프로젝트에 대해 더 구체적인 메모리를 작성할 수 있게 함.

- 해당 프로젝트 내의 모든 채팅은 레벨 1의 계정 수준 메모리를 상속받음.

- 이 전체 영상에서 가장 중요한 문장은 지금까지 본 모든 것이 동일한 근본적인 문제를 가지고 있다는 것임. 바로 AI가 여전히 통제권을 가지고 있다는 점임.

- AI가 무엇을 기억할지, 어디에 저장할지, 언제 기록할지를 결정함.

## **레벨 3: 사용자 소유의 메모리 시스템**

- <strong>개념 및 특징</strong>

- 레벨 3에서는 메모리가 블랙박스(AI 제어)가 아닌, 사용자가 완전히 제어할 수 있는 실제 파일이 됨.

- 이 레벨에서는 AI가 매 세션 시작 시 해당 파일들을 읽고, 사용자가 작업하는 동안 자동으로 업데이트함.

- 모든 세 개의 선도적인 AI 연구소(Anthropic, OpenAI, Gemini)는 현재 AI 시스템을 출시하고 있음.

- 예시로는 Anthropic의 Claude Co-work와 Claude Code, OpenAI의 ChatGPT Work와 ChatGPT Codex, Gemini의 Gemini Spark 등이 있음.

- 이러한 도구를 통해 사용자 자신만의 메모리 시스템을 구축하고 유지할 수 있음.

- <strong>작동 방식</strong>

- 모든 작업 시작 시, AI 시스템은 활성 프로젝트를 위한 라우팅 테이블 역할을 하는 작은 파일을 하나 로드함.

- 사용자가 "마이크로 프레젠테이션 작업을 계속하고 싶어"라고 말하면, AI는 그 테이블을 확인하고 요청을 해당 프로젝트를 소유하는 폴더로 라우팅함.

- 20개 이상의 활성 프로젝트가 있어도 AI는 그 작은 파일 하나만 로드함.

- 프로젝트 폴더 내에서 AI는 최신 프로젝트별 메모리 업데이트를 읽고 모든 관련 자료를 로드하여, 사용자가 마지막 작업 세션으로부터 한 시간, 일주일 또는 일년 후에도 정확히 중단했던 지점부터 작업을 이어나갈 수 있게 함.

- 레벨 3는 시스템이 모든 작업에 대해 다른 경계를 그릴 수 있다는 점을 추가함.

- 글로벌 맥락은 여전히 계승되지만, 이제 사용자가 모든 메모리 기록이 어디에 속해야 할지 결정하고, AI는 수고로운 작업을 대신 수행함.

- <strong>실제 작동 예시: Claude Co-work</strong>

- Claude Co-work에서 작업 공간 폴더가 마운트되어 있음.

- 새로운 세션에서 맥락 없이 "마이크로 아이폰 프레젠테이션 작업을 계속하고 싶어. 지금 어디까지 진행됐고, 다음에는 뭘 해야 할까?"라고 질문함.

- Co-work는 먼저 root memory.md 파일(언급된 작은 파일)을 읽고, 프레젠테이션이 활성 프로젝트로 나열된 것을 확인함.

- 프로젝트 파일이 컨설팅 폴더 내에 있음을 식별한 다음, 프로젝트 파일들을 완전히 읽은 후 업데이트를 제공함.

- 업데이트 내용: 데크는 콘텐츠가 완료되었고 시각적 보완 단계를 기다리고 있으며, 프레젠테이션 날짜가 9월 15일에서 10월 6일로 변경되었음, 3명의 참석자가 추가되어 더 큰 회의실을 예약해야 함.

- 심지어 아직 열려 있는 항목들도 알고 있음.

- <strong>레벨 3의 핵심 특징: 사용자 제어</strong>

- 이 모든 정보는 AI의 블랙박스에서 나온 것이 아님.

- 모두 사용자가 열고, 읽고, 가장 중요하게는 직접 편집할 수 있는 폴더와 일반 텍스트 파일에서 가져온 것임.

- 예를 들어, Obsidian에서 열린 일반 텍스트 파일에서 프레젠테이션 날짜를 10월 6일에서 10월 30일로 변경할 수 있음.

- 이는 사용자에게 메모리 시스템에 대한 완전한 가시성과 제어권을 부여함.

- 초보자에게는 위협적으로 보일 수 있지만, 시작하기 매우 쉬움. 무료 Co-work 툴킷은 1주일 안에 자신만의 Co-work 작업 공간을 구축하는 데 필요한 모든 템플릿을 포함하고 있음.

- <strong>작업 진행 및 메모리 업데이트</strong>

- 동일한 Co-work 세션에서 슬라이드 데크 작업을 계속하여 헤드라인 패스를 진행하고 모든 슬라이드 헤드라인을 명확하게 다듬도록 함.

- AI가 일부 슬라이드의 헤드라인을 다시 작성했지만, 여전히 ESP, SKU, GTM과 같은 약어가 사용된 것을 발견함.

- '슬라이드 헤드라인에 약어를 사용하지 말고, 풀어써라'고 일반 영어로 피드백을 줌.

- 약 1분 후, AI는 전체 패스를 다시 실행하고 모든 슬라이드 제목에서 약어가 제거되었음을 확인해줌.

- 작업 완료 시 "세션이 끝났어. 마무리하자"라고 입력함.

- <strong>내부 작동 방식</strong>: Co-work는 전체 세션을 스캔하여 보존할 가치가 있는 결정, 학습 내용, 진행 상황을 찾아냄.

- 가장 중요하게는, 사용자 승인이 필요한 발견 사항과 AI가 스스로 처리할 수 있는 업데이트를 분리함.

- <strong>승인 필요(input needed) 섹션</strong>: AI는 일회성 약어 수정 사항을 향후 모든 작업 세션을 위한 영구적인 규칙으로 만들 것을 제안함.

- <strong>승인 면제(approval exempt) 섹션</strong>: Co-work는 이미 두 가지를 수행했음.

- 첫째, 헤드라인이 편집되었다는 것을 기록함.            

- 둘째, 항상 먼저 로드하는 작은 파일(root memory.md)을 업데이트함. '다음은 보완 작업'이라는 내용이 더 이상 사실이 아니므로, 다음 세션은 현재 세션이 끝난 지점부터 시작함.

- 요약하면, 작업 세션을 마무리할 때마다 AI는 향후 세션이 따라야 할 개선 사항을 제안하고, 작업 진행 상황으로 메모리 파일을 자동으로 업데이트함.

- <strong>레벨 3 요약</strong>

- 레벨 3는 사용자가 무엇을 저장하고 어디에 저장할지 결정하는 곳이며, AI는 유지보수(수고로운 작업)를 담당함.

- 가장 중요하게는, 모든 변경 사항이 사용자가 직접 열고 편집할 수 있는 일반 텍스트 파일에 저장되어 완전한 가시성을 가짐.

- <strong>작업 공간 전체 라우팅</strong>

- AI 시스템이 올바르게 설정되면, 라우팅은 단일 프로젝트 내뿐만 아니라 전체 작업 공간에 걸쳐 작동함.

- 예를 들어, "마이크로 아이폰 프레젠테이션에 대한 관리자 업데이트 이메일을 초안 작성해줘"라고 말하면, AI는 글쓰기 규칙이 담긴 폴더와 실제 세부 정보가 있는 프로젝트 폴더로 라우팅함.

- 이를 통해 사용자의 말투와 일치하는 정확한 업데이트를 얻을 수 있음.

- 레벨 2에 있는 사용자가 전체 시스템을 처음부터 구축하지 않고 레벨 3 시스템을 원한다면, Co-work Academy에서 완전한 AI 명령 센터 시스템을 얻을 수 있음.

- 거기서 거의 1년 동안 다듬은 미리 구축된 시스템과 자신에게 맞게 조정할 수 있는 단계별 가이드 워크스루를 얻을 수 있음.

## **최종 요약: AI 메모리 레벨별 비교**

- <strong>레벨 1: 글로벌 메모리</strong>

- 메모리 기록이 자동으로 발생하며, 계정 수준이므로 모든 채팅에 적용됨.

- 사용자의 삶의 다양한 역할에 걸쳐 필요한 고수준 정보에는 유용함.

- 그러나 진행 중인 프로젝트와 같은 실제 작업에는 너무 광범위함.

- <strong>레벨 2: 프로젝트 메모리</strong>

- 메모리 기록은 여전히 자동으로 발생하지만, AI가 훨씬 더 좁은 경계를 가져서 해당 작업 흐름에 대한 더 구체적인 맥락을 유지할 수 있음.

- 단점은 AI가 여전히 무엇을 보관할지 선택하므로, 답변이 자신감 있게 오래된 정보일 수 있다는 점임.

- <strong>레벨 3: 사용자 소유의 메모리 시스템</strong>

- 사용자가 무엇을 저장하고 어디에 저장할지에 대한 규칙을 작성하고, AI는 해당 규칙에 따라 유지보수를 수행함.

- 이는 완전한 제어와 최소한의 작업을 동시에 얻을 수 있다는 것을 의미함.

- 단점은 AI 시스템을 설정하는 데 실제 노력이 필요하고, 익숙한 채팅 창과는 다르게 작동할 수 있다는 점임.

- 레벨 3에 대해 더 깊이 이해하고 싶다면, Claude Co-work 시스템을 안내하는 전체 영상이 있음.
