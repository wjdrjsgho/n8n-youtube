## **케미 K3 모델 소개 및 MOA(Mixture of Agents) 활용의 필요성**

- 문샷(Moonshot)이라는 중국 스타트업에서 케미 K3(Kimiko 3)라는 프런티어 모델을 공개했음.

- 해당 모델은 오픈 웨이트(Open Weight)로 풀려 공식 벤치마크상 ChatGPT나 클로드와 유사한 수준의 성능을 보여줘 큰 관심을 받았음.

- 실제로 비개발자들이 한국어로 프롬프트하며 지식 업무를 할 때 성능을 테스트해봤음.

- 
        결론적으로, 다음과 같은 결과를 보였음.

- 대시보드 제작, 웹사이트 랜딩 페이지 제작, 디자인 작업 등 프런트엔드 작업 시에는 꽤 괜찮은 퀄리티를 보여줬음.

- 하지만 복잡한 데이터 분석 작업을 시켰을 때는 예상보다 퀄리티가 아쉬웠음.

- 그러나 같은 케미 K3를 셋 에이전트(Set Agent)의 MOA 형태로 활용해보니, 기존의 ChatGPT 모델을 단독으로 쓰는 것보다 오히려 성능이 향상될 수 있었음.

- 오늘은 단순히 케미 K3가 ChatGPT나 클로드만큼 좋은지를 확인하기보다, 셋 에이전트에서 MOA 기능을 활용하는 방법과 이 기능을 통해 개별 모델보다 어떻게 성능을 높일 수 있는지 알아보려 함.

## **케미 K3 모델의 활용 방식**

- 케미 K3 모델은 7월 27일 오픈 웨이트로 공개됐음.

- 
        이론적으로는 허깅페이스(Hugging Face) 사이트에서 직접 다운로드받아 무료로 돌릴 수도 있음.

- 용량은 약 1.5TB로 추정됨.

- 하지만 공식 배포 권장 구성은 64개 이상의 GPU 가속기를 묶어 활용해야 하므로, 개인 PC에서 직접 돌리기는 현실적으로 어려움.

- 
        따라서 케미 K3를 사용하는 방식은 크게 두 가지임.

- `ea.c` 사이트에서 구독하는 방식: 현재 너무 많은 구독 요청으로 대기자 등록조차 불가함. 문샷 측에서도 구독 서비스를 제대로 제공하기 어려운 상태인 듯함.

- API로 사용하는 방식: 셋 에이전트에서 활용하려면 API 연동이 필요하며, 오픈라우터(OpenRouter)를 통해 API 형태로 활용할 예정임.

## **MOA(Mixture of Agents)와 모델 라우팅의 개념 비교**

- 
        <strong>모델 라우팅(Model Routing)</strong>

- 일의 특성에 따라 해당 작업을 가장 잘 수행할 수 있는 단독 모델을 배분하여 실행시키는 것을 의미함.

- 예시: 회사에서 실무자의 역량에 따라 일을 배분하여 실행하는 것과 유사함.

- 
        <strong>MOA (Mixture of Agents)</strong>

- MOA는 여러 모델들이 '레퍼런스 모델(Reference Model)'로서 자문(consultation)을 제공하고, 최종적으로 '애그리게이터 모델(Aggregator Model)'이 이러한 의견들을 취합하여 도구 실행 및 최종 결정을 통해 결과물을 생성하는 구조임.

- 예시: 회사에서 여러 전문가에게 자문을 받아 최종적으로 대표이사가 의사 결정을 하는 구조와 유사함.

- 애그리게이터 모델은 최종 의사 결정과 툴 콜링(Tool Calling)을 담당하므로, 가장 성능이 좋은 프런티어 모델을 설정하는 것이 일반적임.

- 레퍼런스 모델은 그 외 다양한 모델들을 선택하여 활용 가능함.

## **MOA 설정을 위한 오픈라우터(OpenRouter) 및 셋 에이전트(Set Agent) 연동 방법**

- 
        <strong>오픈라우터 설정</strong>

- `openrouter.ai`에 접속하여 로그인함.

- 'Credit' 섹션에서 크레딧을 추가함.

- 왼쪽 'API Keys'에서 'New Key'를 눌러 API 키를 생성함.

- 
                API 키 생성 시 키 이름, 유효 기간, 크레딧 한도(Credit Limit)를 설정할 수 있음.

- API는 종량제로 비용이 발생하므로, 초기 테스트 시에는 10달러 정도로 한도를 설정하는 것을 추천함.

- 유효 기간은 월별(monthly) 또는 주별(weekly) 등으로 설정 가능함.

- 'Create'를 누르면 생성된 API 키가 뜨며, 이를 복사하여 셋 에이전트에 넣어주면 됨.

- 
        <strong>셋 에이전트에서 MOA 설정 (호스팅 환경 기준)</strong>

- 이전 영상에서 호스팅(Docker Manager)으로 셋 에이전트를 설치한 경우, 도커 매니저의 프로젝트 쪽에서 본인이 활용하는 도커를 찾음.

- 해당 도커의 '관리'를 눌러 대시보드(예: 32776 포트)로 접속함 (로그인 필요 시 아이디/패스워드 입력).

- 대시보드 내 'Keys'에서 'OpenRouter'를 선택하고 복사한 API 키를 붙여넣으면 연동 완료됨.

- 
        <strong>MOA 구성 설정</strong>

- 'Models' 섹션에서 'Mixture of Agents' 설정을 찾음.

- 'Configure'를 눌러 레퍼런스 모델과 애그리게이터 모델을 선택함.

- 레퍼런스 모델은 여러 개(예: 오픈라우터에서 제공하는 Kimiko 3.7 Max 등)를 선택할 수 있으며, 한 개만 선택하는 것도 가능함.

- 애그리게이터 모델은 보통 GPT 3.5/4.0 또는 클로드 오퍼스(Opus) 5를 추천하며, 현재 사용하는 모델(예: 코덱스 연동 GPT 3.5/4.0)을 선택함.

- 원하는 조합을 설정한 후 'Add Preset'을 통해 프리셋으로 추가함.

- 
        <strong>셋 에이전트 데스크톱 앱에서 MOA 설정 (대안)</strong>

- 데스크톱 앱 설치 후, 우측 상단의 설정 아이콘을 누름.

- '모델'에서 'Mixture of Agents' 섹션으로 이동함.

- 여기서도 위에서 설정한 프리셋 모델 조합을 선택하거나 수정할 수 있음.

## **MOA 기능 테스트를 위한 유즈 케이스 및 방법론**

- 
        <strong>가상 시나리오</strong>

- 소규모 커피 브랜드 운영 중, 매출은 늘고 있으나 통장 잔고가 비어가는 상황을 가정함.

- AI에게 이 문제를 해결하기 위한 7월 한 달간의 계획 수립을 요청할 예정임.

- 구체적인 상황: 월말 매출 그래프는 상승했으나, 광고비 증가로 인해 공헌이익이 감소하고 기말 현금도 두 달 연속 감소한 900만원 수준임.

- 
        <strong>제공 자료</strong>

- 총 11개의 파일을 제공함.

- 
                로데이터 (7개 CSV 파일):

- 매출 요약(Sales Summary)

- 광고 캠페인 데이터(Ad Campaign Data)

- 고객 관련 데이터(Customer Data)

- 캘린더 데이터(Calendar Data)

- 현금 스케줄(Cash Schedule)

- 재고 데이터(Inventory Data)

- ...등 다양함.

- 준수해야 할 제약 사항(Constraints).

- 계산 시 활용할 가이드(Calculation Guide).

- 대표의 성향 및 리스크 허용도를 담은 오너 노트(Owner Note).

- 결과물 출력 형식(Output Template).

- 
        <strong>유즈 케이스의 복잡성</strong>

- 모델 성능 비교를 위해 의도적으로 고려할 사항이 많은 복잡한 유즈 케이스를 구성했음.

- 
                구체적인 제약 사항 예시:

- 월초 현금 900만원 보유, 최소 현금 버퍼 150만원 유지.

- 최대 할인율 10%.

- 대표 주차별 가용 시간 40시간, 포장 시간 25시간.

- 
        <strong>프롬프트 및 출력 형식</strong>

- 모든 테스트에 동일하게 짧은 프롬프트만 제공함.

- 
                산출물은 9가지 섹션으로 출력되도록 요청함.

- 핵심 내용 요약

- 현재 상태 진단

- 30일 우선순위

- 보수 기본 성장 시나리오

- 지오 리스크 (Geo Risk)

- 사용할 가정

- 제약 준수

- ...등.

- 
        <strong>데이터 함정(Data Traps)</strong>

- 단순 계산으로는 정답이 나오지 않도록 여러 함정을 심어뒀음.

- 예시: 재고를 단순 총량으로 세면 안 됨 (유통기한 임박 상품, 예약분 등 고려 필요).

- 광고 성과도 로데이터를 단순 합산하면 안 되게 설정함.

## **테스트 모델 및 평가 기준**

- 
        <strong>테스트 모델</strong>

- 단독 모델: 케미 K3, 딥시크(DeepSeek) V4 프로, GPT 3.5/4.0 (기준점 역할).

- MOA 조합 (애그리게이터 모델은 모두 GPT 3.5/4.0으로 설정):

- 레퍼런스 모델 1개: 케미 K3.

- 레퍼런스 모델 2개: 케미 K3 + 딥시크 V4 프로.

- 
        <strong>평가 기준 (총 100점 만점, 클로드 오퍼스 5가 객관적으로 평가)</strong>

- 정확도: 50점.

- 추천 전략의 타당성 (실제 실행 시 의미 여부): 20점.

- 실행력 (제약 조건 안에서 성립하는 제안 여부): 17점.

- 형식 및 근거 (제시된 형식 준수 및 근거 제시 여부): 13점.

- 
        <strong>실제 테스트 진행 방법</strong>

- 셋 에이전트 데스크톱 앱에서 작업할 폴더를 지정하고 필요한 파일들을 추가함.

- 세션에서 프롬프트를 입력한 후, 모델 선택에서 MOA 프리셋(예: 케미 K3 + 딥시크 + GPT 애그리게이터 조합)을 선택하고 요청하면 됨.

- 데스크톱 앱 외 텔레그램이나 슬랙 등에서도 모델 설정만 변경하면 MOA 실행이 가능함.

## **단독 모델별 성능 분석 결과**

- 
        <strong>케미 K3</strong>

- <strong>강점:</strong> 데이터에서 남들이 안 보는 각도로 살펴보는 능력 (예: 7월 주문이 6월 수준일 경우 포장 시간 부족 파악, 유통 채널 구조에 따른 마진 변화 이해).

- <strong>약점:</strong> 제공된 제약 조건을 잘 지키지 못하는 모습 (예: 제약 미표기, 안전 여유 없이 자원 소진, 대표 성향 및 제약 불충분 고려).

- <strong>일관성:</strong> 편차가 매우 컸음 (18점 차이), 매번 실행 시 퀄리티가 들쭉날쭉할 수 있음.

- 
        <strong>딥시크 V4 프로</strong>

- <strong>전반적:</strong> 케미 K3보다 성능이 확실히 떨어졌음.

- <strong>강점:</strong> 재고 로스(loss)가 금액적으로 어느 정도인지 고려하는 부분에서 장점을 보였음.

- <strong>약점:</strong> 케미 K3보다도 제약 조건을 잘 지키지 못했으며, 계산 정확도가 많이 떨어져 단독 평균 점수가 낮았음 (49점).

- <strong>일관성:</strong> 편차가 매우 심했음 (32점 차이), 퀄리티의 변동성이 매우 컸음.

- 
        <strong>GPT 3.5/4.0</strong>

- <strong>강점:</strong> 규칙이나 제약 조건을 매우 잘 지킴 (하드 게이트, 제약 준수에 탁월).

- <strong>약점:</strong> 제약 사항을 너무 잘 지킨 나머지 과도한 긴축 경향을 보이거나, 틀에 박힌 사고만 하는 측면이 있었음. 케미 K3나 딥시크가 보여줬던 독창적인 사고를 고려하지 못하는 모습도 있었음.

- <strong>일관성:</strong> 편차가 거의 없었음 (4점 차이), 꽤 일정하게 높은 퀄리티를 보여줘 안정적임.

- <strong>결론:</strong> 각 모델이 잘하는 것이 달랐으며, GPT는 안정성이 높지만 레퍼런스 모델들의 강점을 모두 갖추지는 못했음.

## **MOA 조합 모델의 성능 및 인사이트**

- 
        <strong>MOA의 최종 점수 비교</strong>

- MOA 조합 모델이 단독 GPT 3.5/4.0보다 확실히 점수가 높았고 편차도 가장 적었음.

- 특히 레퍼런스 모델을 두 개(케미 K3 + 딥시크 V4 프로) 사용한 MOA 조합의 평균 점수가 가장 높았음.

- 단독 GPT 3.5/4.0이 그다음으로 높은 점수를 기록함.

- 단독 케미 K3와 딥시크 V4 프로는 평균 점수가 낮은 편이었음.

- 흥미롭게도, 케미 K3와 딥시크 V4 프로처럼 단독 성능이 낮은 모델들도 GPT 3.5/4.0과 MOA로 조합했을 때는 단독 GPT 3.5/4.0보다 더 높은 스코어를 기록했음.

- 
        <strong>MOA 성능 향상 이유 (레퍼런스 모델의 기여)</strong>

- 단독 GPT는 특정 영역에서 제대로 체크하지 못했으나 (차트의 빈 동그라미), 케미 K3나 딥시크를 자문 모델로 썼을 때 이 영역들을 채워주는 케이스들이 있었음.

- 
                구체적인 기여 요소:

- <strong>딥시크:</strong> 재고 손실을 금액으로 환산하여 분석에 활용함 (단독 GPT는 고려하지 못함).

- <strong>케미 K3 및 딥시크:</strong> 더 완결성 있는 코호트(Cohort) 분석에 기여함 (예: 재구매율을 단순 퍼센트가 아닌 '재구매 2.9회'와 같이 다각도로 분석).

- <strong>케미 K3 및 딥시크:</strong> 콜드브루(Cold Brew)가 판매 없음 처리로 되어야 한다는 점을 파악함 (단독 GPT는 파악하지 못한 함정).

- 
        <strong>MOA의 잠재적 단점 (모든 것이 순증만은 아님)</strong>

- 레퍼런스 모델이 들어오면서 시야는 넓어졌지만, 애그리게이터(GPT)가 혼자였으면 챙겼을 항목(예: 판매 상한, 귀속 중복 등)을 오히려 놓치는 경우도 있었음.

- 
        <strong>가장 큰 시사점: 단점 필터링 효과</strong>

- MOA에서 애그리게이터 모델로 GPT 3.5/4.0을 활용함으로써, 케미 K3나 딥시크가 단독으로 썼을 때 발생했던 제약 조건 미준수 에러들이 많이 필터링됐음.

- 가장 똑똑한 모델(애그리게이터)이 가이드라인을 잘 정리하여 따르게 도와주면서, 레퍼런스 모델들의 장점은 조합하되 단점은 많이 걸러낼 수 있었음.

- 이로 인해 최종 스코어가 올라갔음.

- 
        <strong>MOA의 실제 성능 향상 요약</strong>

- <strong>정확도 측면:</strong> 단독 GPT와 비교했을 때, 레퍼런스 모델을 활용한 MOA는 점수가 유지되거나 -1점 정도 감소했음. 즉, 정확도 자체에는 크게 기여하지 못했음.

- <strong>전략적 측면:</strong> 케미 K3나 딥시크 같은 모델을 레퍼런스로 사용했을 때, 더 다각도에서 분석할 수 있어 전략 점수가 올라가는 것을 확인했음.

- <strong>형식 점수:</strong> 때때로 깎였을 때 레퍼런스 모델이 보완해주는 것을 볼 수 있었음.

## **결론 및 활용 권장 사항**

- 
        <strong>단독 GPT 3.5/4.0 또는 클로드 활용 권장 시점</strong>

- 반복적이고 저위험 업무.

- 형식 준수가 중요한 업무.

- 아직 중국 AI 모델들은 복잡한 조건에서 제약 조건을 지키며 결과물을 생성하는 데 있어 ChatGPT나 클로드만큼의 퀄리티를 보여주지 못하는 듯함.

- 어설프게 API 코스트를 쓰며 중국 AI 모델을 활용하기보다, 클로드나 ChatGPT를 구독하여 넉넉한 사용량으로 쓰는 것이 더 효율적일 수 있음.

- 
        <strong>MOA 기능 활용 권장 시점</strong>

- 매우 중요한 전략적 의사 결정이 필요한 업무 (회사 비유: 대표이사가 혼자 결정하기보다 여러 직원과 다양한 관점에서 회의 후 최종 결정).

- 이러한 관점에서 케미 K3는 꽤 유용한 레퍼런스 모델이 될 수 있음.

- 
        <strong>비용 고려 사항</strong>

- 케미 K3는 오픈라우터 API를 통해 사용할 때 비용 부담이 큼 (테스트 비용 26달러 중 22달러가 케미 K3).

- 토큰을 많이 소비하는 편이라 비용 효율적이지 않음.

- 그러나 레퍼런스 모델로서의 성능이 괜찮기 때문에, 비용을 조금 더 들이더라도 고품질의 결과물을 얻고 싶을 때 활용해볼 수 있음.
