## **AI 작업 파편화 문제와 Buzz의 등장**

- 기존 AI 도구(Claude Code, Codex, Mistral Agent 등)는 개별적으로는 잘 작동함.

- 문제점:

- 결과가 각 툴에 종속되어 하나로 합치거나 검색하기 어려움.

- 한 툴에서 진행한 작업을 다른 툴에서 자연스럽게 이어서 작업하기 까다로움.

- 피드백이 툴별로 흩어져 나중에 찾기 어려움.

- 새롭게 출시한 <strong>Buzz</strong>를 사용하면 이러한 문제를 해결할 수 있음.

- Claude Code, Codex, Mistral Agent 등을 한 곳에서 활용 가능함.

- 심지어 로컬 모델도 불러와 함께 사용할 수 있음.

- 다양한 모델을 하나의 스레드 안에서 컨텍스트를 공유하며 작업 지시 가능함.

- 오늘 다룰 내용: Twitter 창업자 잭 도시가 만든 Block에서 공개한 오픈소스 협업 도구 Buzz에 기존 AI 도구를 붙여 활용하는 방법.

- 대상: 여러 AI 도구 사용 시 결과 파편화로 불편을 겪거나, 결과를 다른 인원과 공유하기 어려웠던 사용자들.

## **Buzz와 Slack 비교: 차이점 및 Buzz의 강점**

- Buzz 공식 설명: "사람과 AI 에이전트가 같은 방을 쓰는 직접 호스팅 가능한 작업 공간" (Direct hostable workspace where humans and AI agents share a room)임.

- AI 에이전트를 팀원처럼 다룬다는 의미임.

- 슬랙 채널에 팀원을 초대하듯, AI 에이전트도 팀원처럼 초대하여 협업할 수 있는 툴임.

- 슬랙에서도 AI 에이전트 초대 및 활용이 가능함.

- 슬랙에는 이미 Claude나 Codex 같은 앱이 존재함.

- 채널에 멘션하여 코딩 작업 등을 맡길 수 있음.

- 커스텀 에이전트나 Mistral Agent 같은 것도 슬랙에 붙여 활용할 수 있음.

- 그럼에도 불구하고 Buzz를 사용하는 이유(차이점):

- <strong>로컬 모델 활용의 용이성:</strong> 슬랙의 AI 기능은 기본적으로 클라우드에서 작업함. 반면 Buzz는 로컬 Claude Code나 로컬 Codex의 기능을 직접 불러와 활용하는 데 유용함.

- <strong>다양한 AI 에이전트 협업 중심:</strong> Buzz는 여러 AI 모델을 AI 에이전트로 활용하고 팀원으로 초대하여 협업하는 것을 메인 포커스로 함.

- Claude Code나 Codex뿐만 아니라 다양한 AI 에이전트를 손쉽게 추가하고 팀원으로 활용할 수 있음.

- 로컬 모델도 직접 설치하고 Buzz에서 작업을 시킬 수 있음.

- <strong>오픈소스 및 커스터마이징:</strong> Buzz는 오픈소스 프로젝트임.

- 슬랙과 달리 무료로 활용할 수 있음.

- 로컬이나 호스팅어 같은 VPS에 직접 호스팅해서 사용하면 코드를 커스텀하여 활용할 수 있음.

## **Buzz 설치 및 AI 모델 활용 방식 결정**

- Buzz 설치 시 가장 헷갈리는 부분은 어디서 돌릴 것인지임.

- <strong>첫 번째: 방(릴레이 서버)을 어디서 운영할지 결정해야 함.</strong>

- Buzz에서 직접 제공하는 호스팅 커뮤니티: 가장 설치하기 쉬운 방식이며, 오늘 가이드에서 활용할 방식임.

- 셀프 호스팅(로컬): 노트북에 직접 설치하여 돌릴 수 있음.

- 셀프 호스팅(자체 서버/VPS): 24시간 돌리고 싶을 때 호스팅어 같은 VPS 서버에 설치하여 돌릴 수 있음.

- <strong>두 번째: Buzz 안에서 돌릴 모델을 어디서 가져올지 결정해야 함.</strong>

- 내 노트북에 설치된 모델: 가장 세팅이 쉬운 방법. 내 노트북에 설치된 Claude Code나 Codex 등을 그대로 가져와 사용할 수 있음.

- 공유 컴퓨트(로컬 모델): 내 PC에 로컬 모델을 설치하고 끌어다가 활용하는 기능임.

- 원격 AI 에이전트 연결: 다른 서버에 AI 에이전트를 설치해 놓고 연결하여 활용할 수 있음.

- 예: 맥미니나 호스팅어에 Mistral Agent를 설치해 놓은 경우 연결하여 활용 가능함.

- Mistral Agent뿐만 아니라 OpenRouter에 있는 다양한 모델 API도 연동하여 활용할 수 있음.

- 대부분의 AI 모델을 연동하여 AI 에이전트로 손쉽게 활용할 수 있음.

- 오늘 진행할 방법: 가장 간단한 Buzz 호스팅 커뮤니티를 활용하고, 내 PC에 있는 Claude Code나 Codex를 활용하여 Buzz를 사용하는 방법임.

## **Buzz 앱 설치 및 초기 설정 단계**

- <strong>Buzz 앱 설치:</strong>

- buzz.xyz 사이트에 접속함.

- 우측 상단 'Get the App'을 클릭하여 설치 파일을 다운로드함. (Mac 및 Windows 지원)

- 다운로드 후 앱을 설치함.

- <strong>앱 설치 후 초기 셋업:</strong>

- <strong>Identity Key 생성:</strong> 프라이빗 키가 생성되며, 별도로 저장해야 함.

- <strong>에이전트 설정:</strong> 본인 PC에 설치된 에이전트(예: Claude Code, Codex)를 감지함. 감지되지 않으면 새로 설치하여 셋업할 수 있음.

- <strong>디폴트 Harness 선택:</strong> Buzz에서 디폴트로 활용할 모델을 선택함. (예: ChatGPT를 주로 사용하면 Codex, Claude Code를 주로 사용하면 Claude Code로 설정 추천). API 키를 입력하여 다른 모델을 선택할 수도 있음. 가성비 측면에서 Claude Code나 Codex 중 활용하는 것을 선택하는 것이 좋음.

- <strong>커뮤니티 조인 또는 생성:</strong> 클라우드 버전을 사용하려면 'Create'를 선택함.

- <strong>빌더 계정 로그인:</strong> 브라우저가 열리고 빌더 계정으로 로그인해야 함. (회원가입 필요 시 진행)

- <strong>Buzz 신원 연결:</strong> 'Pair'를 눌러 코드 인증을 통해 Buzz 아이덴티티를 연결함. 'Buzz Identity Connected' 메시지 확인.

- <strong>커뮤니티 생성:</strong> 빌더 UI에서 'Create Community' 클릭하여 커뮤니티를 추가함.

- 유의사항: 현재 커뮤니티는 5개까지만 생성 가능하며, 테스트로 너무 많이 생성하면 리밋에 걸릴 수 있음.

- 제한 사항: 스토리지 리밋 및 콘텐츠 리텐션(1년치 유지)이 있음. 이러한 제한을 피하려면 셀프 호스팅을 해야 함.

- 원하는 주소 입력 후 커뮤니티 생성.

- 생성된 링크를 통해 접속하여 'Accept & Join'을 누르면 앱으로 접속됨. (슬랙과 유사한 대화방 생성 완료)

## **AI 에이전트 생성 및 설정 방법**

- Buzz는 AI 에이전트를 생성하고 팀원처럼 활용하는 것이 핵심 기능임.

- <strong>에이전트 생성 과정:</strong>

- 왼쪽 '에이전트' 섹션을 클릭함.

- 기본 예시 에이전트(Fizz, Honey, Bumble)가 생성되어 있음. 사용하지 않을 경우 'Stop' 버튼으로 중지시킬 수 있음.

- 새로운 에이전트 생성: '+' 버튼을 누르고 'Create Agent'를 선택함.

- 원하는 아이콘을 추가함.

- 에이전트 이름을 설정함.

- <strong>에이전트 인스트럭션(시스템 프롬프트):</strong> 이 에이전트가 항상 참고해야 할 지침을 작성함. (동일 모델을 사용하더라도 시스템 프롬프트에 따라 다르게 작동 가능)

- <strong>AI Configuration 설정:</strong>

- 'Default Harness': 이전에 설정한 기본 모델(예: Codex)이 자동 적용됨.

- 'Run On': 보통 'This Computer'를 선택함.

- 'Advanced - 누가 인스트럭션을 보낼 수 있는가': 기본은 'Only Me'. 팀원들과 협업 시 'Anyone' 또는 'Select People'로 특정 인원을 추가할 수 있음.

- 'Parallelism': 병렬로 돌릴 개수를 설정하나, 기본값으로 두어도 됨.

- <strong>다른 모델 설정 (커스터마이징):</strong>

- 'Customize'를 클릭하여 다른 Harness를 선택할 수 있음.

- 예시:

- Claude Code 선택 후 모델(예: Opus) 선택 가능.

- Mistral Agent (PC에 설치된 경우) 선택 후 Codex 모델 중 선택 가능.

- Open Claude, Open Code, Grok Build, Cursor 등도 설정 가능.

- Buzz 에이전트에서는 Entropic, OpenAI, OpenRouter 등을 선택하여 활용할 수 있으며, OpenRouter 선택 시 API 키를 넣어 다양한 모델을 활용할 수 있음.

- <strong>예시 에이전트 설정:</strong>

- <strong>해석 담당 에이전트:</strong>

- 역할: 지원 사업 공고 해석 담당.

- 인스트럭션: 특정 폴더의 내용을 읽고 작업, 판별 및 출력, 안전 내용 등을 설정.

- 모델: Opus 1 Million Context.

- <strong>반박 담당 에이전트:</strong>

- 역할: 해석 내용에 대한 반박 담당.

- 인스트럭션 및 Harness만 변경하여 설정함.

- <strong>에이전트 카드 정보 확인:</strong>

- 'Runtime' 탭: AI 에이전트의 설정(Buzz ACP 연동, MCP 사용 여부 등)을 확인할 수 있음.

- 'Channels' 탭: AI 에이전트가 추가된 채널을 보여줌. 여기서 'Add to Channel'을 통해 채널에 추가할 수 있음.

- 'Memory' 탭: AI 에이전트별로 필요한 내용이 자동으로 저장되며, 다음 작업 시 로드되어 활용됨.

## **Buzz 에이전트의 정보 접근 방식**

- Buzz는 기본적으로 설치된 PC의 `.buzz` 폴더 내 세부 파일들을 통해 정보를 읽고 활용함.

- `.buzz` 폴더 안에 `agents.md` 파일이 존재함.

- `agents.md` 파일에는 디렉토리 구조, 코어 가이드라인, 비커밋, 현재 활성화된 에이전트 목록 등이 정리되어 있음.

- <strong>기본 제공 스킬:</strong>

- Claude Code 및 Codex 설정 시 Buzz CLI라는 스킬이 제공됨.

- 이 스킬은 Buzz 활용 방법을 안내하며, 에이전트가 작업을 잘 수행하도록 도움.

- <strong>글로벌 설정 활용:</strong>

- Claude Code나 Codex에 글로벌로 적용되는 스킬이나 MCP(Master Control Program)는 Buzz에서 자동으로 로드하여 활용함.

- 버즈에서도 항상 특정 스킬이나 MCP를 활용하고 싶다면, 글로벌로 설정해 두면 됨.

- <strong>프로젝트별 스킬 활용:</strong>

- 특정 프로젝트 안에서만 작동하는 스킬은 Buzz에서도 해당 프로젝트 내 스킬을 활용하도록 요청하여 사용할 수 있음.

- 구체적으로 어떤 스킬을 활용할지 에이전트 인스트럭션에 명시할 수도 있음.

- 결론적으로, `.buzz` 폴더 내 `agents.md` 및 관련 파일, 기본 제공 스킬, 그리고 글로벌/프로젝트별 스킬을 참고하여 Buzz가 작업을 수행함.

## **Buzz를 활용한 AI 협업 시나리오 예시: 지원 사업 공고 검토**

- <strong>시나리오 설정:</strong> 지원 사업 공고를 다운로드받아 우리 업체가 신청 자격이 되는지 확인하는 작업을 수행함.

- <strong>작업 분담:</strong>

- Claude Code (해석 담당): 지원 공고 내용 해석.

- Codex (반박 담당): 해석 내용에 대한 반박을 담당하여 문제점 검토.

- <strong>채널 설정:</strong>

- '테스트' 채널을 생성함. (예: '다양한 기능 테스트하는 채널', Public 채널)

- 생성된 채널에 '해석 담당' 에이전트와 '반박 담당' 에이전트를 추가함.

- <strong>작업 요청 방법:</strong>

- 멘션(@)을 사용하여 두 에이전트에게 동시에 작업을 요청함.

- 프롬프트 예시: "@해석담당 케이스요 디지털 캐빌리티 지원 사업 신청 자격을 해석하고, 반박담당에게 반박 요청을 해 줘라. @반박담당 해석 내용을 보고 반박을 진행해 줘."

- <strong>사전 준비 파일:</strong>

- Buzz 폴더 안에 `support_program/research` 폴더를 만들고 필요한 파일들을 샘플로 생성함.

- `reference` 폴더: 회사 정보, 소프트웨어 히스토리 파일.

- `case` 폴더: 지원 공고에 대한 세부 내용을 정리한 파일.

- AI 에이전트들이 이 파일들을 참고하여 작업하게 됨.

- <strong>작업 진행 및 결과:</strong>

- 왼쪽 패널에서 에이전트들의 실시간 활동을 확인할 수 있음. 이모지로 내용 확인 여부 표시됨.

- <strong>해석 담당 (Claude Code)의 답변:</strong>

- 예비 검토를 통해 공고 내용을 확인하고, 신청 자격, 제외 대상 사업, 사업비, 제출 서류 등에 대한 확인이 필요하다고 정리함.

- '반박 담당'에게 반박을 부탁하며, 특히 어떤 부분을 집중적으로 봐주면 좋겠는지 멘션으로 전달함.

- <strong>반박 담당 (Codex)의 답변:</strong>

- 해석 담당을 태그하며, 원본과 레퍼런스를 독립적으로 대조한 반박 내용을 제시함.

- 지적 사항을 제시하고, 근거 조항, 근거 값, 출처 파일, 심각도 등을 함께 정리함.

- 최종 판정은 사람이 해야 한다고 안내함.

- <strong>해석 담당의 재검토:</strong> 반박 담당의 피드백을 검토하여 재해석한 최종 답변을 반영하고, 사용자에게 확인 필요하다는 멘션을 보냄.

- <strong>협업의 장점:</strong>

- 객관적인 문제점 발견: 작업한 AI 에이전트가 아닌 다른 AI 에이전트에게 리뷰를 요청함으로써 더 객관적으로 검토할 수 있음.

- 한 눈에 파악 가능한 업무 흐름: 모든 작업 과정이 같은 스레드에서 진행되어 나중에 업무 흐름을 쉽게 확인할 수 있음.

- 로컬 실행 히스토리 확인: Codex 같은 경우, ChatGPT 앱에서 Buzz를 통한 요청(시스템 프롬프트, 에이전트 인스트럭션, 코어 메모리, 채널 정보 등 포함) 및 답변, 결과 파일 생성 히스토리를 확인할 수 있음.

## **로컬 모델 설정 및 팀원 초대 기능**

- <strong>로컬 모델 설정 방법:</strong>

- 왼쪽 하단의 'Settings' 메뉴에 접속함.

- 'Compute' 탭을 선택함.

- 모델을 설정하지 않았다면 모델 선택 옵션이 나타남. 'Fits Well'이라는 초록색 표시가 있는 모델은 현재 PC에서 사용 가능한 모델임.

- 원하는 모델(예: Gemma 4 26B)을 선택하고 'Share this machine'을 켜주면, Buzz가 자동으로 로컬 모델을 다운로드하고 서빙함.

- 설정이 완료되면 '에이전트' 섹션으로 돌아가 'Buzz Shared Compute' Harness를 사용하여 로컬 모델 기반의 새 에이전트를 생성할 수 있음.

- 이렇게 생성된 로컬 모델 에이전트에게 DM을 보내면 답변을 받을 수 있음. (로컬 모델이라 속도가 빠르지는 않지만 무료로 활용 가능)

- <strong>팀원 초대 및 협업:</strong>

- Buzz 커뮤니티에 다른 인원을 초대할 수 있음.

- 'Settings' 메뉴의 'Invite' 섹션에서 초대 가능함.

- 초대 링크를 제공하거나, 초대할 사람의 퍼블릭 키(각 사용자마다 고유)를 받아 추가할 수 있음.

- 초대된 팀원들은 호스트가 설정해 놓은 AI 에이전트를 함께 활용하거나, 호스트의 고성능 PC에 설정된 로컬 모델을 공유하여 사용할 수 있음.

- 이를 통해 조직 내에서 동일한 AI 에이전트를 활용하여 협업 시스템을 구축할 수 있음.

- 결론적으로 Buzz는 모든 AI 에이전트 관련 툴들을 손쉽게 연동하고 같은 세션에서 컨텍스트를 공유하며 활용하기 좋은 슬랙과 같은 채팅 툴임.

## **Buzz의 한계점**

- <strong>모바일 앱의 미완성도:</strong>

- 모바일 앱(Google Play 스토어, 앱스토어)으로도 설치 가능하나, 아직 활발히 개발 중이라 버그가 많음.

- 슬랙과 비교했을 때 완성도가 떨어짐.

- 지속적인 업데이트를 통해 개선될 것으로 예상됨.

- <strong>승인 게이트 및 파일 표시 기능 미완성:</strong>

- AI 에이전트 작업 중 권한 요청 같은 상황이 발생할 때, 슬랙이나 텔레그램처럼 버튼으로 바로 승인하는 기능이 아직 제대로 구현되지 않음. 메시지로 요청만 가능하여 부자연스러움.

- 파일 생성 시 Buzz에 바로 첨부하여 쉽게 확인할 수 있는 기능이 아직 부족함.

- 이러한 기능들도 향후 개선될 예정임.

- <strong>호스팅 커뮤니티 사용 시 로컬 PC 의존성:</strong>

- 호스팅 커뮤니티는 릴레이만 제공하고 모델은 보통 내 PC에서 돌아감.

- PC가 꺼지면 모델을 원격(모바일 등)으로 돌리기 어렵다는 단점이 있음.

- 해결책: 릴레이 서버와 모델을 모두 셀프 호스팅하여 24시간 돌아가게 만들고, 이를 모바일로 연동해야 함. 이 경우 번거로움이 존재함.

- <strong>잦은 업데이트 및 수동 관리:</strong>

- 아직 활발히 개발 중인 앱이라 업데이트가 자주 발생함.

- 업데이트를 수동으로 챙겨야 하며, 인앱 업데이트 시 에러가 발생하는 경우도 있어 Buzz.xyz 사이트에서 앱을 삭제하고 재설치하는 방식으로 업데이트해야 할 수 있음.

- 현재는 데모에 가까운 앱이므로 지속적인 사용자 관리가 필요함.

## **결론**

- Buzz는 다양한 AI 에이전트를 직원처럼 추가하고 업무 협업을 손쉽게 돕는 도구로 유용하게 활용될 수 있음.
